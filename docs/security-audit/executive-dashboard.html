Why this matters — reasoning

  • FIPS posture (F-001). On any IL5/IL6 host with FIPS mode enabled, unguarded hashlib.md5(...) raises ValueError. Dshell’s JA3 fingerprint and SSL blacklist would crash on the first matching connection. Wrapping in hashlib.new(..., usedforsecurity=False) is the canonical Python 3.9+ idiom for non-security hashing in FIPS environments.
  • Elasticsearch exfil (F-002). A network forensic tool that ships sensitive packet metadata to an unauthenticated, plaintext datastore by default is the worst-case data-spill scenario for a DoD enclave. The hardened defaults force operators to make an explicit, auditable choice to deviate.
  • Runtime crashes (F-003, F-004). These are not "may happen" — ssh-pubkey.py referenced sys.stderr without an import, and riphttp.py read payload before it was bound. Both would have fired on legitimate traffic. They suggest the test surface needs broadening.
  • Bare except (F-005). Beyond the formal STIG violation, a network-facing parser that silently swallows SystemExit / KeyboardInterrupt / parser errors is hostile to incident response — the analyst can’t tell capture errors from a malformed packet.
  • eval/getattr (F-008). The eval was over a whitelist of three strings, so it was not directly exploitable. But it’s a STIG pattern-flag and an automatic disqualifier in many federal code-review templates. Cheap to fix; benefits future scanner runs.
